# ADR-0011 · 凭据加密落盘：密钥与数据同机，会话标识只存哈希

**决策**：租户记录（登录名、加密的 access token、真实 scopes、创建与访问时间）落在 `<DATA_DIR>/store.json`，形状 `{ version: 1, tenants: [...] }`；写用临时文件 + rename，权限 0600。`DATA_DIR` 默认 `.data/`（已 gitignore），线上 `/var/lib/triage360`（部署脚本建目录、归服务账号、700）。token 用 AES-256-GCM 加密，每条随机 12 字节 iv 与 16 字节 authTag 随密文以 base64 存放；密钥是 `<DATA_DIR>/store.key` 里 32 字节随机数，首次启动生成、0600。会话标识本身不落盘，只存 SHA-256 哈希（`idHash`），查找按哈希比对。撤销 = 整条移除、写盘后重读确认（`store.delete` 返回布尔，API 验证失败回 500）；30 天未访问的租户在启动、每小时一次的扫描与每次查找时清理。`lastSeenAt` 续期每小时最多落盘一次。第二档授权在途期间租户被撤销时，回调拒绝落盘（不凭作废标识重建租户）。

**原因**：#13 的两条删除义务要求「撤销」是可验证的物理删除、30 天未访问自动清除；凭据一旦明文落盘，备份、快照、误传的文件都等于泄露 token。密钥与数据同机同目录是满足这两条的最小实现：进程重启后会话还在（ADR-0010 留下的「会话只在内存」缺口在这里补上），备份与迁移只需搬一个目录。会话标识只存哈希，拿到账本的人拿不到可用的 Bearer；token 是密文，拿到账本的人读不走凭据。文件形状带 `version`：localStorage 之外的第二个长命键，改形状时旧文件要认得出来。

**被放弃的选项**：凭据明文（备份即泄露）；外部 KMS 托管密钥（单机、单进程、个人项目，多一条依赖与故障链，收益要多实例才出现）；密钥塞进环境变量（deploy.env 由 root 持有、systemd 注入，与 0600 文件同一信任级，但轮换与迁移更麻烦，还会进进程环境）；会话标识的哈希当 token 的 AAD（更紧，但换密钥或改哈希就要迁移全部密文，v1 不需要）；把数据目录放进检出（重新克隆/重置会连带凭据，已否决）。

**已知缺口，刻意留着**：密钥与数据同目录——服务器被完全控制（root 或进程内存被读）时两者都能拿到；自陈屏写明「数据库文件泄露不导致凭据泄露」与「挡不住服务器被完全控制」两句，不夸大。Windows 的 `chmod` 只映射只读位，0600 的实际效果要在 Linux 上复验（部署后 `ls -l` 看一次）。备份策略不在 v1：删除义务保证的是撤销动作本身物理且当场验证，已有备份里的旧副本不在射程内（`docs/PRD.md` §0.4 的射程口径）。演示租户与真实租户同一套存储，等 #15 接演示账号时再定刷新与锁的落点。
