# ADR-0013 · 「为什么是这几条」：规则定序，模型只说一句；输入只有元数据，失败回落规则句

**决策**：单卡理由走服务端同步通道——`POST /api/reason`（Bearer 会话标识，必须是已有租户），服务端用 `server/reason.ts` 调 DeepSeek 的 OpenAI 兼容端点（`https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`），把模型输出的一句话原样回给面板。上行只有卡片元数据的白名单：`title`、`reason`（档位标识）、`learned`（`{ group, hits }`，命中学习加权时才有；`group` 是来源分组键，可能就是 `owner/repo`）、`dueAt`、`duePrecision`、`updatedAt`；正文、评论、diff 与标签一概不送。请求显式关闭思考模式（`thinking: {type: "disabled"}`）：官方 Thinking Mode 文档写明 `deepseek-flash` 默认开启 thinking、默认 effort 为 `high`，而一句措辞不需要推理链，开着只会烧掉 2 秒预算。系统提示钉死三件事：排序与档位已由规则引擎定稿，模型只负责措辞（≤60 字）；有 `learned` 时必须同时说出档位原因与学习信号，没有时一个字都不提学习；合并卡的其余来源由界面另行标注，模型不列举来源。服务端超时 1800ms，面板客户端另设 2000ms 兜底；服务端没配钥匙回 503、超时回 504、其余上游故障回 502，面板在任何一种失败（含没有真会话、样例屏）都回落到本机确定的规则句，卡片上永远有字。合并卡只对表头取理由，其余来源在句子后以「（这张卡还来自 X）」标注带出，不各写一条。服务端日志只记结果、耗时与失败类型（HTTP 状态码），不记标题、提示词或上游原文。启动时先向 `/models` 握一次手，把 DNS + TLS 的冷启动成本挡在首个点击之外。

**原因**：排序是产品的硬承诺（ADR-0005、ADR-0009），把措辞交给模型的前提是它改不动顺序——所以模型只拿到已经定稿的 `reason` 与 `learned`，不拿候选集合，也不返回任何排序信号。2 秒是交互承诺：同步等待 + 超时回落，比「转圈到天荒地老」更接近 PRD 说的「不退化成等转圈」；失败时用户看到的那句话与模型无关，因此质量下限由本机决定。输入只送元数据，是因为模型侧的数据出口越窄，自陈屏的承诺越好兑现：正文与评论从未出现在上行载荷里，这一点不依赖提示词自觉。合并卡只解释表头：`reason` 属于表头（ADR-0006），给每条来源各写一句等于把「一张卡」讲成「两件事」，也让同一张卡的档位出现两种说法。学习信号必须与档位同句出现（ADR-0009 的交界）：只提学习会让人以为位置全靠历史行为，只提档位则漏掉了同档内为什么是它。合并标注放在界面而不是提示词里：它是结构性事实，不该由模型是否听话决定。

**被放弃的选项**：把 DeepSeek key 放进前端构建（凭据会随静态资源发给每个访客）；把正文、评论或 diff 一起上行换「更懂」的措辞（越过托管纪律与字段边界）；让模型参与排序或返回分数（规则与措辞会互相污染，顺序不再可复现）；在打开清单时批量预生成每张卡的理由（违背「针对单条」的同步承诺，成本与首屏一起涨）；用界面模板完全替代模型（PRD 的 AI 出口要求措辞层，且学习信号需要与档位合成一句自然语言）；对模型输出做硬截断（会在句子中间切刀，改为提示词约束 ≤60 字，超长时按原样显示）；把合并卡的其余来源也送进提示词让模型自己带出（同一件事有两个出口，标注会出现两次或措辞不一致）。

**已知缺口，刻意留着**：措辞质量只走手工验收（`docs/PRD.md` 的 Testing Decisions 把 AI 文案质量列在自动化测试之外），本票不新增 seam 测试。60 字上限是提示词约束而非硬校验，模型偶尔超长时照常显示，不截断。`/api/reason` 没有按租户限流：入口由会话标识挡住，演示规模下先不加，配额问题留给上量之后。冷启动由 `/models` 预热缓解，但预热失败时首个点击仍可能撞上 1800ms 超时并回落——回落是设计内行为，不是丢句。模型句不缓存：刷新后再问同一张卡会重新调用，换来的是 `learned` 与档位变化后措辞能跟上；句子生成后卡片上没有原地重问入口，句子在拖拽时会整批作废（拖过之后档位不再是位置的完整解释）。理由只用中文：面板目前只有中文界面。Gitee / Jira / 飞书的真实接入不影响这条通道——上行只认元数据，不认平台。
