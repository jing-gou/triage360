# ADR-0007 · 手动顺序是构建器的注入输入，作用在合并之后

**决策**：seam 1 增加可选注入 `manualOrder?: readonly string[]`（`src/core/today-list.ts`）：访客手动排过的**卡片标识**按他留下的次序排好。**省略即纯规则序**；给了之后，出现在这个表里的卡一律在前、次序由表里的位置决定，没排过的保持规则序跟在后面。落盘在界面这一侧（`src/panel/manual-order.ts`，浏览器 localStorage），构建器不伸手读存储。手动这一票排在**合并之后**。

界面一次落盘写的是**整份可见顺序**，不是「被拖过的那一张」。所以拖一次之后，屏幕上所有已有卡片都进了手动区，规则打分此后可动的只剩新出现的条目。这是「顺序被记住」（AC#1）最省的实现：一份数组、无需给每张卡加「动过没有」的第二个概念，而且刷新后访客看到的正是他离开时那一屏。它同时是一次全清单的接管——这条要写在界面上，弹窗说的就是这句。

**为什么顺序决策进 seam 1 而不是界面里 sort**：界面自己 sort 一遍，代码少两行，但「手动优先于规则打分」这句话在门内就没有任何断言看着它了。spec 的免测清单里划出去的是「拖拽交互与视觉」——那是手势与手感，坏在眼前；顺序口径坏起来是静默的：把两次 sort 的先后调换，界面上仍然「有个顺序」，只是访客排的那份被规则覆盖掉，而他要到下次刷新才发现。两处各排一次还会分叉：构建器排完合并卡，界面再按 id 找手动位置，`mergedFrom` 那层谁当表头的问题就在两个地方各解一遍。

**为什么作用在合并之后**：`manualOrder` 装的是界面上看得见的卡。合并把一条来源收进另一条底下，被收的那条不再是卡，可它可能正躺在手动表里（用户并卡之前拖过它）。若手动序先于合并生效，它会被当成独立条目提到最前、进而当上这一组的**表头**，于是整张卡的 `reason` 从 `overdue` 掉成它自己的 `noDeadline`——正面撞 ADR-0006「表头站在这一组最紧急的那一档」。放在合并之后，表里那些不再是卡 id 的条目自动落空，一句特判都不用写（`tests/manual-order.test.ts` 最后一条钉的就是这个次序）。

**为什么存标识而不是标题**：标题会被上游改掉。`id` 的跨轮次稳定性由两件事一起给：编码集中在一处（`makeTaskId`，`src/core/provider.ts:76-78`），以及 `remoteId` 取的是源站不变的编号而不是会变的内容（ADR-0004）。

**代价**：
- **一次拖拽之后，规则只对新条目说话**。已经排在手动区的卡片此后变逾期也不会往前挤——它落在未排区最前面，读起来像「被埋了」。这是那句「我有一票」的价格：手动区是访客划的地盘，规则不进去 rearrange。界面不给「这条是你排的」这类常驻标记（常态要安静），唯一的说明是首次拖拽那一次弹窗，所以弹窗必须把「整份顺序归你了」说清，说轻了就是骗。#6 的视觉强度只按档位上色，被手动拖到第 4 位的逾期卡仍然显示「已逾期」——颜色和位置不一致这件事，v1 交给访客自己解释。
- **表头换人 ⇒ 那张卡的位置丢**。合并组里非表头那条后来居上时，卡片 id 变了，手动表里记的旧 id 落空，它从手动区掉进未排区。不发生数据丢失，但访客会看见一张卡自己挪了位置。v1 四家各至多一对重复项，概率低。
- **换浏览器或清空站点数据就回到规则序**。这份顺序没有服务端副本，而 #13（T11）的 AC 写着「30 天未访问自动清除，**且覆盖排序记录**」。这个口径本 ADR 一度留成疑问句，现已由 `ADR-0008`（2026-11-17 定 A 支）合上：#13 那两条删除义务的范围是**服务端有的那些**，这份本地顺序由浏览器自己负责——撤销授权之后它仍在这台机器上。#13 的自陈屏因此欠一行本地例外：「怎么清」那一栏要写清这份顺序不在服务端、撤销与 30 天清除都不覆盖它，否则界面就是在做虚假承诺（`DECISIONS.md:60` 那条删除义务的失守点）。跨设备同步本身在 spec 的 Out of Scope 里。
- **只做鼠标拖拽**：HTML5 drag-and-drop，触屏不响应（移动端在 Out of Scope 里）。键盘只能到「Tab 到关闭按钮、回车关掉弹窗」这一步：拖本身没有键盘路径，弹窗也没做 Esc 与焦点圈定。这是真实缺口，v1 记账不做。
- 陈旧 id 不主动清理：构建器忽略认不出的条目，而界面每次落盘写的是「本轮全部可见卡的 id」，所以一次拖拽顺带把垃圾带走。存储不会长。

**被放弃的选项**：把位置塞进 `Task` 当第 9 键（八键是跨平台最小形状，顺序是清单这一侧的结论，与 `reason`、`mergedFrom` 同一个理由）；做成 `pinned: boolean`（表达不了「第 3 位」这种完整次序，而 AC#1 要的就是整份顺序活过刷新）；复用 `previous` 通道（ADR-0003 的语义是「上一轮有哪些任务」，用来夹带顺序会让下一轮读到它的 provider 多背一件事）；在 localStorage 里存 `{id, at, time}` 的日志（那是 #10 学习闭环的记录形状，现在建了就是替 #10 决定它的存储 schema）；落到服务端存储（今天没有可写的服务端：#11 才是第一条真连、#13 才是第一次落库，现在定 schema 等于替它们决定形状）。
